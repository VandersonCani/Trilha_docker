# Conceitos Aprendidos

## Docker não é uma Máquina Virtual

Inicialmente existia a percepção de que Docker funcionava como múltiplas máquinas virtuais.

Durante o desenvolvimento foi compreendido que Docker trabalha com:

* Containers
* Redes
* Volumes
* Processos isolados

Containers compartilham o kernel do sistema operacional hospedeiro, diferentemente de máquinas virtuais tradicionais.

---

## Comunicação entre Containers

Foi aprendido que containers pertencentes à mesma rede Docker podem se comunicar utilizando o nome do serviço definido no Docker Compose.

Exemplos utilizados:

smartcall-db

smartcall-app

smartcall-nginx

Isso eliminou a necessidade de utilização de endereços IP fixos.

---

## Docker Compose

Foi realizada a migração de uma estrutura baseada em comandos individuais:

docker run

para uma estrutura declarativa utilizando:

docker-compose.yml

Benefícios observados:

* Reprodutibilidade
* Facilidade de manutenção
* Inicialização completa do ambiente através de um único comando
* Infraestrutura definida como código

Comando utilizado:

docker compose up -d

---

## Estrutura YAML

Durante a construção do arquivo docker-compose.yml foi identificado que pequenos erros de sintaxe impedem o funcionamento correto da configuração.

Aprendizado obtido:

Elementos de listas YAML exigem espaço após o hífen.

Exemplo correto:

* "3306:3306"

Foi constatado que a ausência do espaço impede que o parser interprete corretamente a estrutura.

Evidência:

Imagem da validação do docker compose config.

---

## Proxy Reverso com Nginx

Foi implementado um servidor Nginx utilizando a imagem oficial.

Conceitos aprendidos:

* Proxy Reverso
* Encaminhamento de requisições
* Exposição de aplicações através da porta 80
* Isolamento entre aplicação e camada web

O acesso passou de:

http://localhost:5000

para:

http://localhost

Evidência:

Imagem da aplicação acessada através do Nginx.

---

## Bind Mounts

Foi utilizado o conceito de Bind Mount para disponibilizar o arquivo:

nginx.conf

do host para dentro do container.

Aprendizado:

Volumes podem ser utilizados não apenas para dados, mas também para compartilhamento de arquivos de configuração.

---

## Volumes Docker

Este foi um dos conceitos mais importantes aprendidos durante o módulo.

Foi identificado que:

Container ≠ Dados

Os dados persistem em volumes independentes.

Durante a migração para Docker Compose foi criado um novo volume.

Como consequência:

* O banco sistema_chamados foi recriado
* As tabelas não existiam
* O login deixou de funcionar

Aprendizado:

Volume antigo ≠ Volume novo

A troca de volume implica em um novo armazenamento persistente.

## Diagnóstico de Problemas

Durante o módulo foram solucionados diversos problemas reais.

### Conflito de Porta 3306

Causa:

Serviço MySQL do Windows ocupando a porta.

Solução:

Parada do serviço local para liberação da porta ao container.

---

### Banco sem Tabelas

Causa:

Novo volume Docker criado pelo Compose.

Solução:

Importação do dump SQL para o novo volume.

---

### Diferença entre CMD e PowerShell

Foi identificado que:

<

funciona normalmente no CMD.

No PowerShell o operador possui comportamento diferente.

Solução aplicada:

Utilização de docker cp e importação diretamente no ambiente Linux do container.
